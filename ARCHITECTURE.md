# PawFall — Architecture & Contracts

Binding contract for all modules. If your module disagrees with it, your module is wrong. If the contract is wrong/ambiguous, do the sensible thing and record the deviation + "Requests" in your report (`docs/swarm/reports/<id>.md`).

## 1. Vision
**PawFall** is a loving parody of Activision's *Pitfall!* (Atari 2600, 1982) in the KÄSEKRIEG universe. You are **Colby**, an orange tabby jungle explorer (pith helmet, red scarf, green eyes). The villain is **Perring Parkway Pete**, a fat grey rat in a pinstripe suit and black shades with a gold tooth and a cheese stick in his mouth, who has stolen 32 treasures (tuna tins, silver sardines, gold bars, diamond collars) and scattered them across a 120-screen jungle, guarded by rolling logs, cheese wheels, fire, cobras, scorpions, tar pits, quicksand, and croc-infested water. Pete's roadside billboards ("PETE'S PARKWAY PICKLES") dot the jungle and he ambushes you from the canopy on `pete` screens.
Pillars: (1) **faithful, readable Pitfall mechanics** — run, jump, vine-swing, ladders, tunnel shortcuts (3 screens per underground step), croc heads, 20:00 clock, 2000 starting points, 3 lives; (2) **blocky Atari look at 320x192** with a limited palette (`defs.PAL`), plus **2.xD depth**: parallax mountains/tree-lines/clouds, foreground leaf silhouettes, a sky that runs **day -> golden hour -> dusk -> night** as the clock runs down, fireflies at night; (3) **charm and juice** (cat puns, Pete taunts, screen shake, dust, sparkles, popups); (4) **zero assets, zero deps**: all art drawn by code into `PixBuf`s, all audio synthesised (WebAudio live + pure-JS offline rendering for WAV previews), plain ES modules, no bundler needed to run.
Rules: original art only (no Activision assets); sim randomness only from a seeded `createRng` (never `Math.random`); sim/levels/art/audio-render code must run in Node (no DOM at import time); touch only files you own (§3); never edit frozen files.
The next game after this one is a 3D one; keep tooling generic and put reusable tools in `~/src/fun/game-factory`.

## 2. Canonical data
`src/core/defs.js` (read it first): `W,H` (320x192), `LAYOUT` (all y/x anchors), `PAL` (the only colours art may use, plus `shade/mix` of them), `skyFor(t01)`, `TUNING`, `vineAngle/vineTip`, `TREASURES`, `SCORES`, `HAZARD_KINDS`, `EVENTS`, `SFX`, `MUSIC`, `ART` manifest (`node tools/sheet.mjs <module>` validates your art module against it), ScreenDef + hazard entity shapes (in comments).
Coordinates: x right, y down, logical pixels, origin top-left. Entities use **feet** (bottom-centre) as their position. Surface feet at `LAYOUT.surfaceY`, tunnel feet at `LAYOUT.tunnelY`. Player hitbox `TUNING.hitW x hitH`, feet-centred.

## 4. Simulation API (`src/sim/game.js`, owner sim-core)
```js
import { createGame } from './sim/game.js';
const g = createGame({ seed = 1, bus, screenAt, startScreen = 0 });   // screenAt injected (= levels/world.js)
g.update(dt, input);            // fixed step 1/60 (dt <= 1/30)
input = { dx: -1|0|1, dy: -1|0|1 /* -1 up, +1 down */, jump: bool /* held */, jumpPressed: bool /* edge: true for ONE update */ }
```
Read-only state for render/ui/bots: `g.t` (sim seconds), `g.state` ('intro'|'play'|'dying'|'gameover'|'victory'), `g.timeLeft` (s), `g.score`, `g.lives`, `g.screenIdx`, `g.layer` ('surface'|'tunnel' — which layer the *player* is on), `g.screen` (current ScreenDef), `g.player`, `g.ents` (hazard entities of the current screen, both layers), `g.collected` (Set of treasure ids), `g.treasureCount`, `g.visited` (Set of screen idx), `g.vineT` (vine clock), `g.rng`, `g.bus`, `g.stats` ({screens, logHits, deaths}).
`g.player = { x, y /*feet*/, vx, vy, face: -1|1, layer, mode, pose, frame, inv /*s*/, onLadder:boolean, onEnt:id|null, t }`
- `mode` ('ground'|'air'|'climb'|'swing'|'stun'|'sink'|'dying'|'dead'|'win') is sim logic; **`pose` + `frame` is what render draws**: pose in `idle|run|jump|climb|swing|hurt|sink|dead|win` selecting `colby_<pose>` and frame index (sim advances run frames by distance, climb frames by rungs, etc.).
- `sink` sinks `y` below the surface over `TUNING.sinkTime` (render clips Colby at the pit surface), then life lost.
Engine API for hazards (sim-core implements, sim-hazards calls): `g.spawn(kind, props) -> entity`, `g.hurtPoints(n, src)` (log: score -= n, stun, knock back), `g.kill(reason, src)` (life lost: 'fire'|'snake'|'scorpion'|'croc'), `g.sfx(name,x?,y?)`, `g.fx(type,x,y,opts?)`, `g.popup(text,x,y,color?)`, `g.rng`.
**Rules (sim-core):**
- Surface: run left/right at `runSpeed`; `jumpPressed` while grounded -> jump (`jumpV`, keeps horizontal speed, small air control); gravity; land on the path (`surfaceY`), on closed-mouth croc heads (`solidTop`), or in a pit.
- Leaving the screen edge: surface -> `screenIdx ± 1`; tunnel -> `± TUNNEL_STRIDE`; player x wraps to the opposite edge; entities respawn from the new ScreenDef (logs restart from the right edge, etc.); emit `screen`. The world is circular (`((i % N) + N) % N`).
- Pits (`screen.pit`): `hole` with ladder = safe: walking into it drops Colby to the tunnel floor (`tunnel_drop`, no penalty); `tar`/`quick`/`water` (no crocs) = he sinks and loses a life unless he clears it (jump) or crosses on the vine; `croc` = water with 3 crocs (hazards `croc`, `solidTop` when mouth closed; mouth open = lethal). Pit extents = `pit.x0 .. x0+w`. Landing inside the pit extents with feet below the surface (not on a croc) => sink. Feet at/above the surface while horizontally over a pit and not on a croc => falls (gravity), not instant death.
- Vine (`pit.vine`): pivot at pit centre x, `vineTip(cx, g.vineT)`. In the air, tip within `grabR` of Colby's hands (top-centre of the hitbox) => `swing` mode, attached with rigid length; jump (edge) releases with swing tangential velocity; ground contact releases. (Prove with a test that a bot can cross every `vine` pit.)
- Ladder (`under.ladderX`): at the hole, Up/Down climbs between surface and tunnel at `climbSpeed`; at the top, standing on the path; at the bottom, standing on the tunnel floor. Tunnel: walk freely; brick wall at `under.wall` side blocks movement (`brick_bump` sfx once on contact); scorpions are lethal.
- Treasure (`screen.treasure`): touching it collects it (score += value, `treasure` event, sparkle, popup) unless id in `g.collected`. Collecting all `TREASURE_COUNT` => `victory` (score += timeLeft * timeBonusPerSec, state 'victory').
- Timer counts only in 'play'; `timeLeft<=0` => game over ('time'). `lives==0` => game over. Dying: `dying` state `deathTime` (sinking/pose dead), then respawn at the **start of the same screen's left edge, surface layer** (or screen entry edge), `respawnInvuln`, hazards respawn, state 'play'.
- Score: starts `START_SCORE`; log/cheese touch: `-100`, stun, knock back, continues (not a death). Floor at 0.
- Intro: state 'intro' ~1.6 s (banner "COLBY vs PETE", music 'jungle'), then 'play'.
- Determinism: `createGame({seed})` + identical input sequence => identical state (tests assert it).

## 5. Hazards (`src/sim/hazards.js`, owner sim-hazards)
`export const HAZARDS = { log:{init,update,onTouch?}, stilllog, cheese, fire, snake, croc, scorpion }` and `export function spawnScreenHazards(g, screen)` which turns `screen.hazards`, `screen.pit.kind==='croc'` (3 crocs spaced across the pit; staggered phase) and `screen.under.scorp` into entities via `g.spawn`. `logs2`/`logs3` become 2/3 `log` entities ~90/70 px apart. sim-core calls `init(e,g)` once and `update(e,dt,g)` each tick for each live entity, and does the AABB contact test (player hitbox vs `e.x±w/2, e.y-h..e.y`), then applies `e.lethal` ('life' -> `g.kill(kind)`, 'points' -> `g.hurtPoints(TUNING.logHitPenalty)`), subject to player invulnerability and ground-vs-air (a jumping Colby clears logs/fire/snakes whose top is below his feet).
Behaviours: **log** rolls right->left at `speed` (default 46 px/s, varies by screen idx ±), frame advances with distance, wraps back to the right edge; **stilllog** static, lethal 'points'; **cheese** (Pete's wheel) rolls faster (70) with a hop every ~1.2 s, 'points'; **fire** flickers (frame cycle), lethal 'life'; **snake** coiled, sways (frames 0-2), lethal 'life' (contact box narrower than the sprite); **croc** `crocPeriod` cycle: closed (frame 0, `solidTop`, `lethal:null`) / open (frame 1, `lethal:'life'`, `solidTop:false`), open for `crocOpenFrac`; **scorpion** patrols the tunnel floor at 20 px/s between walls/edges, lethal 'life'. Pete (screen.pete): every ~4 s he emits `taunt` (from `TAUNTS` in your module) and `pete_laugh` sfx and tosses a `cheese` from the right edge. Pure functions of (entity, dt); no Math.random.
Hazard entity dims: log 14x8 at feet, stilllog 16x8, cheese 12x12, fire 8x12, snake 8x10, croc 22x10 (top surface at `surfaceY` water line - 2), scorpion 12x8.

## 6. World API (`src/levels/world.js`, owner world-gen)
`screenAt(idx) -> ScreenDef` (shape in defs.js), `export const WORLD = { screens: WORLD_SCREENS, treasures: [{id,type,screen,x}], start: START_SCREEN }`, `treasureScreens()`, memoised, **deterministic** (own seeded LFSR/rng; no state). Rules: 32 treasures (ids 0..31; values spread: 12 tuna, 10 sardine, 6 gold, 4 collar), placed on distinct screens spread around the whole circle (never on screen 0), at x clear of pits/hazards; `hole` pits ~1 in 4 screens (with ladder + under.ladderX == pit centre); tar/quick/water pits ~1 in 4 more (some with `vine`: pit.w 72-84 needs the vine, narrower <= 36 is jumpable, croc pits w 64 with 3 crocs); logs/logs2/logs3/stilllog/cheese/fire/snake mixed by difficulty ramping with distance from screen 0 (symmetrically both ways round the circle); `pete:true` + `mood:'pete'` every ~12th screen (sign + canopy Pete, cheese hazards); mood varies in runs of 3-8 screens; `under.wall` alternates L/R/null; tunnel scorpions on ~1 in 3 screens. A hazard never overlaps the pit or treasure x. `tools/validate-level.mjs` (world-gen) proves: every screen crossable surface-wise by a normal player (jump range ~ 48 px, vine pits crossable only with vine, pits not combined with a hazard that blocks the take-off/landing run), 32 treasures reachable and unique, determinism, no unreachable soft-locks.

## 7. Art & render
### 7.1 Art API (`src/art/<module>.js`)
`export function build() -> { [name]: PixBuf | PixBuf[] }` exactly matching the `ART` rows of that module (size, frame count). Pure & deterministic (`createRng(seed)` / `hash2`); each module builds in <= 400 ms. Use `PixBuf` (`rect, line, ellipse, circle, poly, blit, outline, noise, ramp, shade, mix`, see pixbuf.js). Style: blocky Atari-meets-NES — **1px dark outline (`PAL.outline`) on characters**, 3-4 tone ramps built from `PAL`, light from the upper-left, **readable at 1x**, big simple shapes, no anti-aliasing, no gradients except dithering. Colby is *cute and readable at 16x24*: orange body with darker stripes, cream muzzle/chest, big green eyes, pointy ears poking out of the khaki pith helmet (with red band), red scarf, tail curling up. Characters face right. Validate: `node tools/sheet.mjs <module> --scale 6` then view `out/previews/<module>.png`; measure opaque bounding boxes numerically; iterate at least twice.
Frame semantics: hazards use `e.frame` (rolling frames by distance, croc 0 closed / 1 open, snake sway 0..2). Colby `pose`/`frame` as in §4. `tile_*` water/tar/quick frames animate by time (`floor(t*4) % 3`).
### 7.2 Registry (`src/art/registry.js`, render)
`buildAll() -> { get(name, frame = 0) -> canvas-like drawable, size(name), frames(name), names() }`; Node-safe (returns PixBufs when no DOM). `createRenderer` accepts the registry.
### 7.3 Renderer (`src/render/renderer.js`, owner render)
`createRenderer(canvas, { bus, art, settings }) -> { draw(game, alpha), resize(), setCRT(on), shot() }`. Draws at 320x192 into an offscreen buffer, then integer-scales (pixelated) to the canvas (canvas width/height attributes are set by `resize()` to fill the window at the largest integer scale <= available, letterboxed black).
Painter order: sky bands (`skyFor(timeLeft/TIME_LIMIT)`, banded) + sun/moon + stars (night) -> clouds (slow parallax) -> mountains (0.15x) -> far tree-line (0.3x) -> far canopy -> **screen-scroll parallax**: since the world is screen-flip, parallax layers offset by `(screenIdx*W)` * factor so neighbouring screens line up seamlessly, and a short horizontal slide transition (~0.25 s ease) on screen change -> main canopy + trunks (from `screen.trees`) + decor (bushes/rocks/mushrooms hashed from screen idx) + Pete sign/branch Pete (mood 'pete'/screen.pete) -> vine (pixel line from pivot to tip + knot) -> path strip + dirt + pit (surface tile anim + `pit_depth`, ladder tiles, croc entities) -> tunnel (ceiling, interior, brick walls at `under.wall`, ladder, bats ambient) -> hazard entities (by kind/frame) -> treasure (shimmer frames) -> Colby (mirrored by `face`; sink = clipped at the pit surface; blink when `inv>0`) -> particles (dust/splash/sparkle/stars/popups from the bus) -> **foreground leaf silhouettes** at left/right screen edges (swaying, drawn after Colby, ~2.xD depth) -> night overlay (darkening + fireflies) -> screen-shake -> CRT (optional scanlines/vignette) -> HUD callback (ui-shell `drawHud(ctx, game)`, set via `renderer.hud = fn`) -> overlay callback (`renderer.overlay = fn(ctx)` for menus/title).
Tunnel and surface are both visible simultaneously (Pitfall style): the player is on one layer; the other layer is drawn but unobstructed. Underground is always dark-ish. Performance: pre-render static layers per screen idx into cached offscreen canvases; target 60 fps.
Render is a pure function of game state + time (no sim mutation). Provide `render/scene.js` helper `drawScreenStatic(ctx, art, screen, t)` reused by the title/attract screens and shot tool.

## 8. Events
`bus.emit(type, payload)` per `defs.EVENTS` (payload shapes in the comments there). Sim emits; render/audio/ui subscribe. Audio listens to `sfx`/`music` only. Subscribe at construction time (lifecycle lesson from earlier games).

## 9. Audio (`src/audio/*`)
`audio.js` (audio-sfx): `createAudio(bus, settings) -> { unlock(), setVolume(master,sfx,music), setMute(on), dispose() }` — WebAudio context created lazily on the first user gesture; subscribes to `sfx {name}` and `music {name}`; master/sfx/music buses with compressor. `sfx.js` (audio-sfx): `SFX_NAMES` (= `defs.SFX`), `describe(name) -> voices[]`, `schedule(ctx,dest,voices,t0,opts)` (live) and `renderSfx(name, sr=44100) -> Float32Array`, `stats(pcm) -> {peak,rms,len}` (pure JS offline path, Node-safe, same voices; `node tools/sfx-wav.mjs` writes `out/sfx/<name>.wav`). `music.js` (audio-music): `createMusic(ctx, dest) -> { play(name|null), stop() }` and `renderMusic(name, sr, seconds) -> Float32Array` (offline) with `MUSIC_NAMES`; `node tools/music-wav.mjs` writes `out/music/<name>.wav`. Chiptune character: square/triangle/noise voices, 8-bit feel, light and jaunty — *jungle*: bouncy marimba-ish arpeggio melody in D major at ~132 bpm with a walking bass; *underground*: spooky minor, slower, sparse bass+bleeps; *dusk*: the jungle tune slowed, minor-tinged; *title*: heroic jingle with a cheeky Pete motif (tuba-ish low bass) ; stings: gameover (descending), victory (fanfare). Sound effects are short, punchy, 8-bit (peak <= 1.0, no clipping, 20 ms attack/release anti-click). Every name in `defs.SFX` and `defs.MUSIC` must exist.

## 10. UI shell (`src/main.js`, `src/ui/*`, `src/core/input.js`, owner ui-shell)
`main.js`: boots art registry, audio, bus, renderer, game; fixed-timestep loop (accumulator, 1/60, max 5 steps); handles resize, pause (Esc/P), mute (M), CRT toggle (C), fullscreen (F), settings persistence (`core/settings.js`). Query params for tools/QA: `?autostart=1` (skip title), `?screen=N` (start screen), `?seed=N`, `?bot=1` (autopilot drives), `?time=SECONDS` (set timeLeft, to preview sky phases), `?nosound=1`, `?poll` (no persistent connections). `window.__pawfall = { game, renderer, bus, step(n), setInput }` for the shot/QA tools.
Controls: arrows/WASD move & climb, Space/Z/Up(Up also climbs)/W jump -- keep it classic: **Left/Right run, Up/Down climb, Space or Z or X jump**; gamepad (d-pad/stick + A); touch overlay (`ui/touch.js`) shows on touch devices: d-pad left + jump button right. `input.js` produces the `input` object of §4 (with a proper `jumpPressed` edge).
Screens (state machine in `ui/screens.js`): **title** (logo, attract mode: bot plays in the background of the title scene or the title_scene art with Pete laughing; "PRESS SPACE" blink; hi-scores; options: sound, music, CRT), **intro banner**, **HUD** (Pitfall style: top strip black; score left in `hudTxt`, lives as `colby_life` icons, timer right `MM:SS`, treasure counter `n/32` with a tiny treasure icon; low-time (<60 s) red pulse; Pete taunt banner with `pete_head`), **pause**, **game over** (score, treasures, screens, hi-score table, 3-letter name entry), **victory** (cutscene: Colby cheering with the treasure pile, Pete shaking a fist, tally with time bonus, confetti), **how-to-play** panel. Text via `src/ui/font.js` (`drawText`, 5x7 pixel font). All UI is drawn into the 320x192 buffer (not DOM), so it is screenshot-able.

## 12. Conventions that bit us before
- Numbers via `??` not `||`; subscribe to events at construction; pin conventions (axes, feet anchor, frame semantics) in tests; never write shared `out/` files from tests (use temp dirs); look at art at x6 scale and measure bounding boxes; comments mentioning `Math.random` can trip source-scan tests — word them carefully.
