Runs AFTER factory-content and BEFORE factory-library, factory-guide and factory-surface (they must know about styles; register `styles.*` capabilities in the core registry format, do not edit their files). A style preset is a declarative bundle that selects tooling and conventions for a kind of game. Build: (1) A preset schema (`style.json`, JSON Schema): id, name, description, genre/camera (side-scroller, top-down, 2.5D parallax, isometric, first-person, 3D), render tech (canvas2d pixel, canvas2d vector, WebGL/three.js, raycaster, path-traced/ray-marched shader), resolution and scaling rules, palette policy (locked N-colour ramps vs free), art kit + character kit settings, audio kit settings (chip/FM/orchestral-synth, channel limits, bit depth), fx defaults (CRT, scanlines, bloom, outlines, cel-shading), physics/world-gen choices, input scheme, performance budget, recommended swarm shape and model tiers per role, a verification checklist, pitfalls, and example games (PawFall, catxzzon, KÄSEKRIEG, duum). (2) Seed presets, each with a short theming guide: `retro-8bit-sidescroller` (PawFall as the reference), `retro-16bit`, `pixel-2.5d-parallax`, `cartoon-vector`, `cel-shaded-toon-3d`, `lowpoly-3d`, `raycaster-fps` (duum style), `raytraced-3d` (WebGL/shader path tracing, with a performance fallback tier), `top-down-arcade`, `isometric-tactics`, `ascii-terminal`. Presets for 3D must name concrete zero-dep or CDN-free tech choices and their limits. (3) Theme tokens: a `theme.json` mixin (palette, typography/font kit, UI skin, SFX/music mood, title-screen layout) applied on top of a style, with a validator and a couple of examples (jungle, space, cheese-ratops). (4) Capabilities with JSON-Schema I/O: `styles.list`, `styles.show`, `styles.recommend` (free-text game idea plus constraints like platform, team, budget -> ranked presets with reasons and trade-offs; deterministic scoring), `styles.apply` (write the preset/theme into a project's config and list which kits/libs/skills to install, never overwriting without `--yes`), `styles.validate`. Asset-library descriptors should be taggable by style id (document the tag convention in STYLES.md for factory-library to adopt). Tests: schema validation of all presets, recommendation golden cases (>=12 ideas -> expected top preset), apply is idempotent and non-destructive, theme validation. Docs: `docs/STYLES.md` with a comparison table.
