# How PawFall was made

PawFall was built by a swarm of AI agents working in parallel from one written contract. This page explains how the work was split, what each agent did, and what we learned.

## The shape of the swarm

- **20 agents** in **4 phases**: 17 on Sonnet, 3 on Haiku. The roster is in `.tracker/plan.json` (generated by `npm run plan`), and each agent's manual is in `docs/swarm/prompts/`.
- **Phase 1 (core):** simulation (`sim-core`, `sim-hazards`), the world generator (`world-gen`), Colby and Pete art (`art-colby`), and the renderer (`render`).
- **Phase 2 (content):** jungle scenery (`art-world`), hazards and treasures (`art-critters`), FX and UI sprites (`art-fx`), sound effects (`audio-sfx`), music (`audio-music`), the UI shell (`ui-shell`), and the media tracker (`tracker-media`).
- **Phase 3 (play-test):** the autopilot and the soak tuning (`qa-bot`).
- **Phase 4 (ship):** this site and docs (`site`), and the reusable factory tools that came out of the project (`factory-*`).

Each agent owned a fixed set of files. No agent edited a file it did not own. When a module needed something from another module, it wrote a "Request" in its report instead. Reports live in `docs/swarm/reports/`, and checkpoints in `docs/swarm/progress/`.

## The contract

`ARCHITECTURE.md` and `src/core/defs.js` are the binding contract. They define the 320x192 screen, the 120-screen world, the colour palette (the only colours art may use), the tuning numbers, the event names, and the shapes of screens and hazards. Agents coded against the contract and guarded against missing files with fallbacks. When the contract and a module disagreed, the module was wrong.

## Rules that kept it working

- **Seeded randomness only.** The simulation uses a seeded RNG, so a run can be replayed and tested.
- **Zero dependencies.** Plain ES modules and Node 22. The art is drawn into pixel buffers by code, and the audio is synthesised.
- **Verify, do not assume.** Agents ran the game, took screenshots, and read the bounding boxes of their sprites before reporting done.
- **Checkpoint often.** Agents kept a short progress file, so a fresh agent could resume after a usage limit.
- **Report failures honestly.** Each report lists its deviations from the contract and its mistakes.

## Tools

- `tools/serve.mjs` serves the game locally on port 4781.
- `tools/shot.mjs` takes headless Chrome screenshots, frames and key sequences.
- `tools/botplay.mjs` runs the autopilot over the world, so the world can be checked for reachability and treasure placement.
- `tools/sheet.mjs` builds contact sheets so art can be reviewed at scale.
- `tools/swarm-tracker/` is the live dashboard that showed each agent's progress.

## Learnings

- A contract with exact numbers and anchor points was the thing that let twenty agents work at once. Vague shared interfaces caused most of the rework.
- Small, pixel-level checks (bounding boxes, palette membership) caught more problems than visual review alone.
- Reports that name their own mistakes are more useful to the next agent than polished summaries.

The per-agent reports in `docs/swarm/reports/` have the details.
